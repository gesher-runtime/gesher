# Descriptor-backed stdio, 2026-11-17

The host and Android ELF entry points now use one executable-owned stream
registry. The CRT still owns opaque `FILE` allocation and native close/reopen;
Gesher owns stream locks, input/output buffers, error/EOF indicators and stream
orientation. All data operations reach the common `read`, `write` and 64-bit
`lseek` implementations. An `F_SETFL` change through a duplicate or an inherited
description therefore takes effect at the next actual I/O, including a buffered
append flush. There is no second seek-then-write append decision in stdio.

## Ownership and synchronization

`fdopen` prepares both its stream state and the registry node before the native
CRT can take ownership of the descriptor. Either allocation can fail without
closing the caller's descriptor. A stream's access mode can be narrower than
the underlying descriptor's access; the stream checks its own mode.

The recursive stream lock is shared by host and guest calls. Unlocked functions
use the same buffer without taking that lock, and `ftrylockfile` performs a real
nonblocking attempt. A `fflush(NULL)` traversal pins state objects rather than
raw `FILE` pointers, locks each state, and checks retirement before accessing the
file. `fclose` retires the stream before native close releases its token; a
successful `freopen` resets the existing state and establishes a new OFD.

Line-buffered output is flushed before descriptor input through line-buffered
or unbuffered streams. The final flush callback is registered in an early
executable constructor so output from ordinary application destructors and
earlier application `atexit` registrations is included. Guest process exit
also explicitly flushes after its finalizers. `_exit` remains unflushed.

## Android observations used as the contract

These are observed in the Android 16 sources, rather than inferred from the
new PR's tests or from glibc behavior:

- `fdopen` checks the requested access and sets real `O_APPEND` for mode `a`
  while preserving the descriptor's current offset.
- `fopen` and `freopen` in append modes, including `a+`, initially seek to EOF.
  This differs from glibc's initial `a+` read position and is asserted in the
  Android/Gesher routes, separately from the Linux reference.
- Output flush resets the pending buffer before invoking write callbacks;
  partial progress followed by an error is not retained for a duplicate retry.
- `fflush` on a read-only stream returns `EOF`/`EBADF`. On an update stream
  currently reading, it leaves read-ahead intact.
- `ftello` attempts to flush output, then queries the descriptor offset. A
  flush error can remain in `ferror` while the position query succeeds.
- `setvbuf` with size zero ignores a supplied buffer and chooses a normal
  allocation. It clears EOF and discards read-ahead, attempts to flush even
  when buffering later changes, and falls back on allocation failure.
- Bionic deliberately retries descriptor input after a previous EOF; a later
  successful read does not by itself clear the EOF indicator.
- Successful positioning discards pushback/read-ahead and clears EOF.

uses `getc`/`ungetc`. The shared adapter uses those callbacks and holds one stream

parser. Guest format/argument conversion remains in the existing ABI adapter.

## Validation and remaining integration gates

`python3 tools/test_stdio_contracts.py --sanitize` runs the production portable
buffer core against real files and nonblocking pipes, then extracts the actual
stream adapter and fopen/fdopen/fclose bodies into a declared Linux envelope.
The envelope substitutes Win32 owner/handle boundaries and native FILE token
allocation, and uses glibc formatting/scanning through the same I/O callbacks.
It tests allocation failure ownership, 64-bit positions, dynamic append,
stream permissions, wide output, scanning look-ahead, recursive/try locks,
unlocked output and concurrent flush-all/close/reuse. A child invocation checks
that final output includes an older application exit handler. The independent
Linux public-API reference runs separately; documented Android/glibc
differences are asserted in the Android/Gesher routes only.

Actual MinGW/Windows linkage and the executable/DLL owner boundary still
require `stdio_ofd_test.exe` in the Windows lifecycle track. The same public
corpus is included by the Android ELF `libc_test`. The Windows track also
verifies the exit-handler child's real output file. The Linux envelope is not
evidence that these Windows execution gates have passed.

The public corpus includes a nonblocking pipe read. It therefore requires the
descriptor layer's pipe implementation to honor `O_NONBLOCK`; recording the
flag while allowing native blocking reads is a failing implementation. The
stdio adapter routes every such read through that shared descriptor path and
does not invent a separate pipe behavior. PR68's pipe work must satisfy this
gate before the integrated feature is considered ready.
