# General Windows CI regressions

The general Windows jobs on `a1bb8b09` failed after the other 49 jobs passed.
The failures have several shared causes; their numerous missing-output checks
are not independent runtime bugs.

- Single-process stand-ins attempted to read the real device's sealed account
  file after earlier server tests created it. They now use process-local account
  state. The native server-only DPAPI guard remains unchanged. A regression
  verifies that stand-ins ignore and preserve both protected and legacy records,
  while the persistent service continues to reject an invalid protected record.
- Server-owned locale broadcasts inherited the incoming app Binder identity.
  Internal broadcast dispatch now clears and restores transport identity after
  the external service entry point has authenticated the caller. Delegated
  package identity and code-lifetime checks remain in the broadcast controller.
- Sweeping gaps between ELF unwind ranges interpreted OpenSSL assembly data
  tables as FS instructions and modified them. Code without unwind information
  is now discovered from function symbols and direct control-flow edges. The
  stripped partial-unwind fixture checks hidden code and executable data that
  deliberately resembles an FS instruction.
- The native chooser's receipt depended on PowerShell module autoloading after
  profile redirection. SHA256 receipts now use the .NET implementation directly.
- Empty optional APK arguments were converted to an empty argv entry by a
  PowerShell if-expression. No-metadata runs now keep an actual empty array.
- Older checks expected plaintext accounts and log fields removed to avoid
  printing private values. They now require the sealed-store header, absence of
  plaintext storage, and the current invariant diagnostics. The lifecycle
  permission fixture now declares the CAMERA permission it requests.

Local checks on the changed source/runtime:

- Original services track: zero failures.
- Native chooser: all eight modes passed.
- OpenSSL: 12 key-generation/signature cycles passed; the previous runtime
  reproduced failures with the same unmodified ELF fixture. An older main
  runtime also passed all 12 cycles.
- Stripped partial-unwind fixture: hidden direct-call target, unchanged
  executable data, stack guards, flags and thread checks passed.
- Actual Binder locale change: activity relaunched, registered and manifest
  receivers both received LOCALE_CHANGED.
- Actual isolated device: alarms delivered after process exit, service delivery,
  repeating cancellation and alarm-clock delivery passed; authenticator checks
  produced a sealed account file without a plaintext account file.

The complete offline security integration passed all 67 checks, including the
new account-isolation case and the existing native role-denial checks. Optional
GmsCore metadata suites are separate from this no-APK CI configuration.

Hosted run `42394872423` exposed an additional controller-fixture timeout on
Windows 2025: its successful descendant handshake reached 1.61 seconds against
a 1.5-second main deadline. Process, job, writer and handle retirement were all
proved, but the parent had not been observed exiting before the deadline.
Positive protocol controls now have a bounded 3.5-second main budget; intended
timeout controls retain 1.5 seconds, and all existing 5-second evidence and
cleanup limits remain. Fresh hosted CI is still required for the resulting source.

The focused controlled-worker run `42395481505` passed on both Windows 2022
and Windows 2025. The exact source pins now select the fixture bytes at
`c62c0ea4`; controller/worker identities, execution gates and negative metadata
controls remain unchanged. The complete workflow must pass on the final source.

Hosted run `42396101292` passed 49 jobs; the general Windows jobs each reported
only two genuine failures. Synthetic negative-control FAIL markers in the full
logs are expected and do not contribute to that failure count.

The ordered-broadcast behavior itself passed, but its evidence receipt failed
because a Windows PowerShell child inherited pwsh's module search path and could
not discover the `Get-FileHash` script module. The same failure was reproduced
locally with that module path. Integration helpers now load their own host's
Utility module explicitly; the identical reproduction then passed. This also
covers the downstream WebView, launcher, icon and package-event receipts.

The standalone GMS app had no attached SystemServer process record. Its ordinary
non-ACK broadcast now reaches the existing sender-policy path only when both the
claimed and actual Binder PID are the current process and no process is attached.
Ordered/ACK delivery and external application-thread/PID/UID validation are unchanged.
Actual standalone and separate-Binder GMS SDK/Firebase delivery both passed.

The complete 67-check security integration passed again in Windows PowerShell
with pwsh's restricted module search path, including ordered-delivery forged-thread
negatives, native role denials, sealed-store restart and capability retirement.
The five-image chain was rebuilt for the updated Java artifact. A fresh complete
hosted run is required before merging.
