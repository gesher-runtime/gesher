# Legacy bootstrap and registry CI checkpoint

Source checkpoint: `c65cc4f8371db5db1d80167a0607f85879b86803`. Registry-only workflow run `40780883011` is pending. The workflow builds the real CMake fixture, checks current-run producer and archive identity, logs compiler and command, and runs bounded real-process controls on both Windows runners. Its success cannot qualify Binder transport, lifetime concurrency, the legacy routes or AOT.

The legacy routes remain broken: fresh CLI processes and old direct server, Main, service and native harness actors do not hold the private writer's owned launch registration. `ControlWorker` rejects reserved roots after handoff; `SpawnOwned` also refuses reserved packages when `g_writer` is true. Current independent CLI startup therefore does not become authorized merely by setting `GESHER_BINDER`. The original route assertions must be preserved and exercised.

A potential server-owned command relay would accept a bounded command enum and validated arguments, start a fixed trusted helper suspended, publish its actual retained CreateProcess handle on the private writer, and resume it only after publication. Its output, termination and cancellation must be propagated with bounded ownership and cleanup. No request can select a UID, process identity, executable, inherited capability or writer. An explicit restricted host-child registration operation would need to be separately designed and tested alongside revoke and PID reuse.

The unresolved boundary is authorization of the initial request: guest code and host CLI currently share a Windows user and token, so a same-user named-pipe ACL cannot tell them apart. A file, pipe name, environment variable, PID, birth, executable path or bearer token exposed to the guest is not a trustworthy credential. Granting host-command semantics on that basis would admit a guest to host authority. A safe design needs an OS-enforced host/guest distinction, a retained and privately transferred launch capability, or an individually proven command surface safe for arbitrary guest invocation. This is a concrete security design gap, not a reason to disable admission or remove tests. Legacy harnesses also need an owned bootstrap which starts and registers their actors without giving actors the writer.
