# Common rules for every gesher track agent

Project: gesher ports AOSP ART and the Android framework to Windows (github.com/gesher-runtime/gesher, PUBLIC; AOSP pinned at android-16.0.0_r4, BUILD_ID BP4A.251205.006). Phases 0-2 are done and merged to main: dalvikvm.exe runs on Windows, framework.jar is on the boot class path, libandroid_runtime's natives are builtin, and gesher-app (app/) drives an APK's Activity to onResume headless, tested in CI and through an Inno Setup installer.

Read first: docs/architecture.md, docs/roadmap.md, docs/framework-natives.md, docs/framework-build.md, docs/decisions/0004..0013 (esp. 0005 posix layer, 0006 managed ABI, 0008 linux ABI, 0011-0013), app/README.md, CMakeLists.txt, cmake/aosp/*.cmake, compat/, tools/fetch-aosp.sh + aosp.lock, .github/workflows/ci.yml and framework.yml, tests/windows/run-tests.ps1.

Working rules:
- Owner's local-load follow-up (2026-10-26, reaffirmed 2026-10-27): use CI
  for every C/C++, Java and C# compilation, including small Gesher-only
  fixtures. Do not start local compilers or execute native/JVM/C# fixtures;
  prepare their sources and CI checks instead. Local source inspection,
  edits, Git operations and lightweight script parsing may continue.
- Work ONLY in your worktree, on your branch. Commit and push to your branch often (small commits, English, existing style). Every commit message ends with: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never merge into other branches or main, never open PRs: the coordinator merges.
- Stay in your file domain (given in your brief). Shared files (CMakeLists.txt, .github/workflows/ci.yml, docs/roadmap.md, app/Main.java) get minimal, additive edits only; list each such edit in your final report.
- Windows tests: put your checks in tests/windows/tracks/NN-<track>.ps1 (dot-sourced by run-tests.ps1; use Check, RunDex, NoDrive, $Dir, $root, $bcp, $failed). Heavy new CI build work goes in your own reusable workflow (.github/workflows/<track>.yml with workflow_call) wired into ci.yml with a job + `needs`, like framework.yml; artifacts it adds must be downloaded by the test/package jobs.
- CI first. Local disk and memory are limited: do NOT build AOSP pieces locally or use WSL. Use CI: `gh workflow run ci.yml -R gesher-runtime/gesher --ref <your-branch>`, then `gh run watch <id> -R gesher-runtime/gesher --exit-status --interval 120` (run in background; do independent work while it runs). Read job logs instead of downloading artifacts, using `gh run view <id> --log` after completion or `gh api repos/gesher-runtime/gesher/actions/jobs/<job-id>/logs` for a completed job. Cancel your own superseded runs. Caches: there were "Egress is over the account limit" warnings - don't churn caches needlessly. Runners: windows-2022 and windows-2025 for tests, 16 GB / 4 cores.
- Toolchain pitfalls: llvm-mingw cross-compile with -Werror. Native code is MS x64 ABI except JNI, which is System V (JNICALL is sysv_abi; NATIVEHELPER_SYSV_JNI_ENTRY; GESHER_JNI wraps JNI tables; tools/jni-sysv-patch.py). Builtin native libraries register with gesher_register_builtin_library; natives found by name (Java_*) must be in a symbol table, since JNIEXPORT exports nothing. AOSP fetches are blobless sparse clones: sparse-checkout patterns must be additive; never `git ls-tree -l` on them. javac against libcore needs -XDstringConcat=inline. PowerShell -replace takes a regex. wsl.exe expands $vars in inline -c strings (use script files).
- A dumb word-based network filter (NetFree) sometimes blocks text or requests; if something is blocked, rephrase/encode or write to a file and carry on.
- Do not touch C:\work\gesher-backup-2026-10-23 or other worktrees.
- Work fully to the goal without asking for permission; go step by step, each step verified in CI before building on it. Update your roadmap section's checkboxes only for what CI verified, and document your work (docs/<topic>.md, a new ADR in docs/decisions/ numbered from 0014 upward, with your track name in the filename to avoid collisions, e.g. 0014-graphics-*.md; the coordinator renumbers if needed).
- Be honest. Final report (your last message): CI run ids, what is verified (quote the PASS lines), what remains stand-in or unverified, every edit outside your domain, and anything the coordinator must do.
- GitHub API rate limit: always watch runs with `gh run watch <id> -R gesher-runtime/gesher --exit-status --interval 120` (never the 3 s default); on HTTP 403 back off ~10 minutes. Keep the "Status and next steps" section current with every push, so nothing is lost if you are stopped.
