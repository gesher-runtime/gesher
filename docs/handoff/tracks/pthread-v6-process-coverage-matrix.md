# Pthread process-authority coverage matrix: v6 experimental source

Source boundary: winpthreads upstream commit `a3d93999ef0521681d45e445c39964a7af0f593f`, with the exact supplier patch in Gesher commit `58dd958f4ddf514b1457295d4b8e7043bc8402af`. The [input manifest](pthread-v6-source-inputs.sha256) covers all 27 C, header and assembly files in `src`, `src/libgcc`, and `include`; the 22 unmodified files were checked against the pinned Git blob IDs, and the five changed files were produced by reverse/apply checks. Actual v6 run `40955412343` passed all nine jobs, three roles and six Windows receipts; independent audit is `C:/work/gesher-ci-review/pthread-409554-independent-audit.md`. This is an isolated probe, not a shipped supplier.

The [function matrix](pthread-v6-source-function-matrix.tsv) enumerates 268 parsed definitions, including 168 external-or-conditional definitions, and the [header matrix](pthread-v6-header-symbol-matrix.tsv) inventories 290 relevant header tags, macros, inline functions, prototypes and data. Each function row names source line, direct calls and direct state flags. `PROBE_OWNER_DISPATCH` means the source contains a conditional dispatch, not that lifetime/semantics are proven; `CLOCK_AUTHORITY` similarly only indicates a source pattern. `LOCAL_VALUE_ONLY` identifies eight manually inspected attribute routines described below; `REVIEW` is unresolved, not a pure-local finding. The inventory is reproducible with `python tools/host-pthread-authority/source_coverage_inventory.py <expanded-source-root>` and Universal Ctags 6.2.1. Universal Ctags and lexical calls do not expand macros, resolve function pointers or conditional compilation, identify actual PE exports, or prove no dependency; compare against binary export/import tables and both compile configurations before marking coverage complete. Symbol overloads and internal functions are deliberately retained. The line numbers refer to the expanded candidate, not an unpatched upstream checkout.

The descriptor is explicitly experimental. A generated forwarding layer is a candidate only after an exact pinned export and internal-call graph has established function signatures, data exports, callback ownership and loader admission. Generating wrappers from declarations without resolving direct internal state accesses, static archives and TLS hooks would merely hide bypasses. Normal production/fault role remains macro-OFF; no product integration or release is asserted by the matrix.
