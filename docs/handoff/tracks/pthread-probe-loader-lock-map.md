# Probe loader API and lock map

Scope: exact expanded source for the attach-cache candidate following eec80c5c; source lines refer to `C:/work/gesher-pthread-cache-expanded/mingw-w64-libraries/winpthreads/src`. This is a source audit, not a general lock-order proof. The inventory does not capture indirect loader operations by the CRT, allocator, callbacks or code outside this supplier. Conditional branches, toolchain runtime and dynamically linked clients need independent validation.

| Loader-sensitive code | Direct path and source observation | Remaining obligation |
|---|---|---|
| `identity_probe_discover`, `gesher_sync_probe_discover` in `thread.c` | `gesher_owner_admit` invokes both during image process attach, before calling `register_alias`; only after registration succeeds does it publish the two cached pointers and Interlocked state. These use GetModuleHandle/GetProcAddress/GetModuleHandleEx/VirtualQuery; the identity and sync hot owner functions read Interlocked state and cached pointer only. | Prove actual TLS/CRT order, no calls before attach from supported product callbacks, correct failure/rollback and no publication race. Attach occurs under loader lock. Existing 409680 tests predate the cache; its cold-mode tests need fresh CI. |
| `gesher_alias_probe_register` | Loader APIs and region checks precede the alias SRW acquire, but registration itself still runs in the process-attach loader context. Publication holds key then alias lock; unregister holds alias lock. 409680 forces one publisher versus static-DLL attach collision and releases it from a controller without loader calls. | No complete loader/alias/key graph proof; include unregister, loader teardown, concurrent reader rules, failed attach, all supported callback paths and reference lifetime. |
| `gesher_key_new` | VirtualQuery/GetModuleHandle/GetModuleHandleEx for callback ownership occur before `_pthread_key_lock` in key create. | Module lookup/unload race, non-image code policy and caller obligations, supported process roles and nonlocal exits still need proof. |
| `gesher_key_release` | FreeLibrary occurs after key lock is dropped on create failure/delete and after callback returns in ordinary cleanup. `gesher_cleanup_held` invokes callbacks after dropping key and spin locks. | A native thread's cleanup can run inside its TLS callback under loader lock; release/FreeLibrary then runs in that context. Key ref transfer, nonlocal exit, reentrancy, shutdown and lock order remain open. The 409545 native DLL callback case demonstrates one passing schedule only. |
| `clock_anchor`, `gesher_clock_register_v1` in `clock.c` | CPU-clock anchor discovery/validation calls loader APIs; registration finds CompareObjectHandles before acquiring clock SRW. `pthread_getcpuclockid` obtains its duplicated target handle through a registry operation and returns from that operation before anchor resolution. | Audit all callers, special CPU-clock use inside callbacks/locks, DLL-only pinning, startup and shutdown. No claim that every clock path is loader-free. |
| `winpthreads_init` in `misc.c` | Constructor queries kernel32/kernelbase functions and stores per-image pointers. | Prove startup ordering relative to static and dynamic TLS, `clock` and name/handle calls, actual supported executable and DLL roles, and process shutdown. |

The former direct path `pthread_key_delete` holding key lock -> registry mutex -> `gesher_sync_probe_owner` -> GetModuleHandleEx is removed from the cache candidate's source because the sync wrapper no longer does loader lookup on the admitted hot path. This does not by itself exclude earlier admission, other loader paths, callback code or external application locks. The cache is probe-only and its source/CI must be independently reviewed before any activation claim.
