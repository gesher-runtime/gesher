# Owned UDP nonblocking native I/O

Source-only candidate, not qualified until actual current-source Linux/HOST/both-guest component and coherent full audits. The unrelated private pthread supplier experiment and all prior TCP/alias/cancellation/close gates remain unchanged.

RegisterSocket takes native endpoint ownership. First registration detects AF_INET/AF_INET6 UDP through standard SO_PROTOCOL_INFOW and configures native nonblocking mode before publication, including imported initially blocking handles. Logical blocking is retained in the shared description; dup/dup2 do not configure a second endpoint. On setup failure the unpublished CRT reservation and transferred native socket close, with errno preserved. FIONBIO/F_SETFL thereafter change logical mode only for managed UDP.

SendOwned/RecvOwned cover send/recv families, fd read/write and vectored I/O. Logical blocking snapshots mode/timeout once and retries bounded native calls over short poll slices with one deadline. Native calls and close-publication checks share the original description.error_mutex, so a retired numeric socket is not queried after reuse. Deferred cancellation occurs outside locks and owning poll snapshots. Explicit caller-reference and outer vector cleanup support the pinned host's nonlocal cancellation; no live OFD/registry entry is reset by that cleanup.

Poll observes managed UDP through a supported non-overlapped, permanently nonblocking MSG_PEEK. A zero-byte datagram remains data; an oversized datagram's one-byte peek is data, not an error, and leaves full bytes for the caller. WSAECONNRESET becomes unconditional POLLERR, not POLLPRI; stale EAGAIN removes read readiness. No native SO_ERROR query or temporary alias mode flip occurs. Unrequested queued data is suppressed using bounded ten-millisecond slices and a fresh nonblocking re-sample after each pause and at the deadline. A mixed two-endpoint HOST witness injects and positively samples the second requested endpoint AFTER the first native sample, requires its actual readiness before half the300ms budget, and proves both payloads survive; the observer is invoked only once.

Independent oracle410699/source dce44a30 proves both Windows hosts: repeated MSG_PEEK retains reset10054; ordinary recv consumes it; subsequent poll0/recv10035 establishes old state cleared; a new send then produces new read256/peek10054/ordinary10054 and finalpoll0. No shadow token is introduced. The original imported public HOST ECONNRESET contract stays intact. Normal creation's existing SIO_UDP_CONNRESET-off policy is preserved; Linux connected ICMP/ECONNREFUSED and positive SO_ERROR consumption remain a separate explicit policy gap, not silently changed here.

The identical public fixture adds IPv4/6 logical alias mode, MSG_DONTWAIT, finite blocking receive timeout, zero/one/8192 payloads, repeated full peeks, immediate readable and finite unrequested-priority polls, scalar/vector/message I/O, two real readers competing for one datagram and deterministic Linux/HOST pending-entry cancellation through scalar/message/vector calls. Android Bionic has no pthread_cancel/PTHREAD_CANCELED API; the entire cancellation helper/callsite is outside __BIONIC__ and both guests must log that explicit API boundary while retaining all their data/timeout/alias/reader controls. This follows the official Android status document (https://android.googlesource.com/platform/bionic/+/master/docs/status.md), not a runtime skip or an added guest extension. The cancellation request is queued before public I/O entry; this exercises nonlocal caller/vector cleanup and is explicitly not a blocked-wait witness. HOST also checks reference count returns exactly to baseline and both initially nonblocking and blocking imported native reset inputs, alias repeated peeks, ordinary error consumption and a new error after a positively cleared state.

All old assertions, suppliers, role checks and negative controls remain mandatory. The component's Linux reference and both Windows consumers must require the new actual rows and execute HOST plus x86_64/arm64-v8a guests. Diagnostic oracle remains on its own branch; publishing this component must not rerun an unchanged characterization as qualification. No local native/JVM/C# compilation or fixture execution is allowed.
