# Sync-family owner dispatch experiment

The generated supplier delta is strictly gated by `GESHER_PTHREAD_ROUTING_PROBE`. The table is a separate versioned diagnostic ABI, not a production contract. `pthread-sync-probe-entries.tsv` records the 75 exact source definitions selected by the generator: mutex, condition, rwlock, barrier, spin and semaphore families, their attribute and 32/64 time entry points, and the cross-TU `do_sema_b_wait_intern` helper. The public headers, DLL exports and static archive must still be compared independently: ctags-derived source definitions cannot prove coverage of every alias, macro or precompiled consumer.

Each DLL entry first resolves the static host's descriptor, validates size, version and host image ownership for every function, and then invokes the typed host function. A missing descriptor on a host with a known identity/clock anchor aborts; a host with neither anchor still takes the preexisting standalone fallback, which does not distinguish an unadvertised static provider. That topology is not admitted as safe by this experiment. The actual product executable/import/late-load topology has not been established and no source is enabled in production.

The semaphore wrappers copy errno between the owner and caller CRT for ordinary returns, restoring the prior owner errno when the domains differ. This does not handle cancellation, pthread_exit or other nonlocal transfers across the wrapper; it is not a complete cross-CRT solution. The current fixture cannot establish separate CRT errno behavior. A generator must not silently turn this bounded technique into a production guarantee.

The mixed-family fixture exercises explicitly initialized mutex, condition, semaphore and rwlock objects with cross-image calls, cancellation cleanup and a DLL-initialized mutex used by the static host after actual DLL unload; the pinned mutex object's vtable is checked to reside in the host image. A malformed descriptor version must abort before a mutex call. These controls do not prove static initializer races, concurrent ref/destroy, existing objects created before admission, DLL unload concurrent with callbacks, condition timing aliases, barriers, spin locks, separate CRTs, or nonlocal unwinding. They do not replace existing identity, 338 destructor, +8 handle, foreign exit, clock, fault or role controls. Full source/role peer review and exact CI are required before interpreting any result.

The subsequent rwlock-only probe forces two valid concurrent read-lock callers to observe the static initializer before either can finish: the host caller holds the common initialization guard, and the DLL caller signals an actual failed try-lock before that guard is released. The pinned supplier's recheck returned EINVAL if another initializer had won, although its caller already treats EBUSY as the retry/success case. In the probe only, that recheck now returns EBUSY; the macro-OFF source retains its prior behavior. A separate bounded Linux reference checks two concurrent readers of a static rwlock. This fixture does not establish condition-variable initialization races: concurrently waiting on the same condition with different mutexes can violate the condition dynamic-binding contract, so that scenario is not used as a required control. Object destruction races and complete POSIX behavior remain open.
