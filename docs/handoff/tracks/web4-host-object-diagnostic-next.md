The 2022 runtime was 131.0.2903.86. The observed `E_NOINTERFACE` is a concrete limitation of that runner/runtime, not a reason to omit the nested-frame assertion. The older runtime's remaining frame events were not subscribed after the exception. A follow-up can record the capability failure independently before attempting other registrations, but must still fail the original selected nested requirement.

Microsoft documents access-time iframe origin checking for the allowed origins: https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2frame.addhostobjecttoscript?view=webview2-dotnet-1.0.4258.31 . The earlier different fixture run 40683759274 observed CDP `://` for its sandbox context on both runners. That does not identify the sandbox context in 40715394989 or prove the cause of its host-object result. The 2025 frame-attributed return `ok:5` and controlled source show the selected call completed; the native call queue was not individually printed. This is a concrete failed exclusion control, and the host-object API alone is not qualified as an opaque-origin guard.

Proposed changed-source diagnostic, pending peer: preserve the same sandbox markup, origin allowlist, native per-frame identities and failing opaque-denial assertion. Print the complete native call queue in a finally block even on failure. On the same run subscribe to CDP execution-context events and binding calls before navigation, using the already exercised realm probe session handling. Correlate controlled fixture labels, CDP session/context/frame and native frame observations; log the engine context origin and unique ID, while explicitly treating labels as fixture correlation, not authority or production COM-to-CDP identity. Require an observed selected sandbox context and binding before evaluating the assertion; distinguish a missing CDP observation from an accepted host call, and retain all raw events. A same-run opaque context plus matching native call would narrow the discrepancy but would not establish the engine implementation cause or a security-safe production mapping.

Use bounded phases and the existing external process deadline, without relaxing the denial or nested requirements. Do not combine this diagnostic with a production fix; lifecycle, redirects, OOPIF races and other opaque forms remain unproven. Review source and evidence mapping before any new CI dispatch; do not retry the unchanged failure.
