# Track brief: arm64-2

Remaining translator/guest ABI contracts from ADR 0047 and docs/arm64.md.
Reserved ADR: 0067. Branch `wip/arm64-2` starts from integration after aot2;
create its own worktree under C:\work when implementation starts.
Follow track-rules.md, including CI-only AOSP builds and no WSL.

Required work:
- Guest-generated executable code: register/protect/invalidate guest JIT pages
  and translated blocks, including self-modification and mprotect transitions.
- Deliver guest signal handlers with an actual arm64 siginfo/ucontext/register
  layout and honor changes on return; cover synchronous faults and queued
  signals without exposing a host context as an arm64 one.
- Implement LSE atomics with the memory ordering/concurrency Android advertises;
  ensure HWCAP reporting agrees with supported instructions. Test contention
  and failed compare/exchange through real guest code.
- Marshal HFAs passed and returned by value, mixed floating/integer register
  exhaustion, nested callbacks and variadic/long-double cases described by
  ADR 0047. Coordinate binary128 libc/libm implementations with native3.
- Honor guest floating-point rounding/exception environment, including every
  fesetround mode, per-thread state and nested guest/host crossings.
- Audit the documented per-nesting/per-thread translated-code cache and guest
  stack limits. Verify bounded allocation and cleanup; measure overhead with
  the established native comparison rather than weakening the benchmark.

Domain: compat/arm64, guest ABI/loader interfaces and focused native tests.
Coordinate ELF loader changes with exec3 and syscall/common shim changes with
native3. Keep guest ELF code and callbacks exercised in both JNI and native
process contexts, single-process/device APKs, both Windows runners. Required
TIC-80, native2/native3, package and both e2e checks must remain green.
