# Proposed production listener route: review required

Source base is unqualified Web4 worktree at 3a4a45ed; existing `webMessage` authorizes child callbacks using a document URI and `postFrameMessage`, which cannot distinguish opaque security origin. Do not ship or integrate that path. The production prototype must replace listener traffic end to end rather than connect CDP observations to COM frames by labels. Other WebMessage/ports/geolocation paths retain their existing gates and scope.

1. In `compat/webview/webview_host.cc`, create a host-generation-owned listener coordinator on the WebView STA. Before navigation, subscribe to CDP context-created/destroyed/cleared, target-attach/detach and frame-tree events; sequentially await Runtime/Page enable, binding registration and flattened recursive autoattach. For each paused target await session Runtime/Page enable and binding installation, then resume under one existing absolute monotonic budget, including error and destruction cleanup. Timeout or unknown target/session disables listener delivery and reports failure; no busy wait or synchronous STA wait. `ICoreWebView2_11::CallDevToolsProtocolMethodForSession` and `ICoreWebView2DevToolsProtocolEventReceivedEventArgs2::get_SessionId` were introduced in SDK 1.0.1185.39: https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2_11?view=webview2-1.0.4258.31 and https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2devtoolsprotocoleventreceivedeventargs2?view=webview2-1.0.4258.31 . Both actual runtimes 131/155 exercised these calls in 409112; capability failure must not fall back to URL or silently claim support.
2. Register the existing document-start script through `SetDocumentScript` only after coordinator initialization completes and before navigation is released. Modify `PageScripts.messageListener` to create its object at document start using a captured initial realm origin as provisional visibility gate, preserving app script order and message codecs; invoke a CDP binding with name and bounded payload. This page gate is untrusted, cannot authorize, and direct access to binding is expected. Its race, tamper and every-context visibility must be tested; failure means this candidate does not satisfy AndroidX. Do not use raw top-level host objects.
3. For each `Runtime.bindingCalled`, the native coordinator resolves `(generation, session, numeric context id)` only to a previously observed nonambiguous live default-world record with engine unique context ID, frame ID, engine origin and proven parent/root classification. Apply `ListenerOrigins` rules in Java against that engine origin, never URI or payload; make opaque/unrecognized origin explicit and fail closed. Bound sizes/queues. An immutable delivery ticket carries host generation, target session, unique ID, listener registration generation, engine origin and main/child classification across JNI into provider UI queue. Recheck that exact ticket at callback delivery; listener removal, host teardown, context destruction/clear and target detach revoke tickets. Any uncertainty, duplicate context or ID reuse rejects rather than reattributes. Do not relabel a previously accepted call at navigation start.
4. Replace `SupportLib` reply key `long document` with retained ticket identity and listener-object identity. On reply, recheck eligibility on STA then invoke session-specific `Runtime.evaluate` using `uniqueContextId` and a correctly JSON-encoded dispatch expression directed to that object; drop on protocol failure or retirement, never fall back to top page/new document. Serialization must retain strings and ArrayBuffer codec and ordering. No lock across JNI callbacks or async CDP operations; host destruction invalidates and drains bounded tasks, retains Web3 query pools/deadlines.

This is a proposed prototype, not a proven secure contract. Open blockers before acceptance include CDP context events ordered relative to binding and navigation commit, queued precommit delivery versus retirement, session attach/detach/reuse and unique ID semantics across processes, frame parent/root truth including initial empty documents, CDP debugger contention and missing events, bootstrap integrity against hostile parent/page and first-script execution in every context, wildcard/ports/file/opaque/inherited origin semantics, actual reply isolation and cancellation. Test with actual APK bridge in both single/device modes, frame siblings/nested/OOPIF, hostile direct binding and forged labels, sandbox, about:blank/srcdoc, redirect, held navigation, remove/destroy/detach and numeric reuse; retain all 14 Web3 original gates, fixed deadlines and full/package/e2e checks. No untested child feature may be advertised as qualified. Standalone 409112 and 409118 prove selected observations only, not application delivery or race safety.
