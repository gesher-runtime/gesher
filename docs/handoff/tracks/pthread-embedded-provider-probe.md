# Static archive embedded in a DLL: isolated routing probe

The 7e5 product source builds `gesher_arm64.dll` with `-static` and loads it from a statically linked host; the same source also defines standalone ARM64 smoke/fpcr/fpsr hosts. This establishes a supported build topology, not that a particular winpthread archive member is present in an installed binary. The qualified 409490 product inventory was too limited to prove the presence or absence of that member. This experiment uses an actual `-shared -static` DLL with the separately built probe supplier archive and checks its exact identity/sync/data exports and lack of `libwinpthread-1.dll` import.

The probe changes compile-time `DLL_EXPORT` dispatch into image-aware dispatch: the provider compares its own function address's image with the executable image. The executable continues locally; a different participating image may use the executable's verified descriptors. A static archive's `.CRT$XLF` callback handles process attach/detach registration of its data alias and suppresses its independent per-thread cleanup only when attached to an advertised owner. This modifies the diagnostic supplier only; production macro-OFF behavior is unchanged.

The test compares same-thread identities and shared key-table pointer, creates a host-owned mutex through the embedded provider, keeps a foreign thread alive after the DLL returns to host code, actually unloads the DLL, uses/destroys the mutex, and checks native thread exit, exact destructor, stale identity, clock and the original +8 bound. It does not test the actual translator binary, all pthread operations, a DLL unloading while a caller is still executing its code, arbitrary third-party static providers, separate CRTs, process termination, or full loader-lock ordering. The normal caller still owns the lifetime of code it is executing. Host without known anchors remains an explicitly unqualified admission case, not automatic proof of unsupported or safe fallback. A separate executable with no host anchors tests a standalone statically embedded DLL: its local key, foreign native exit/destructor and physical unload. This is still a fixture, not proof of the actual smoke/fpcr/fpsr hosts.

The image test invokes loader APIs from paths which may already hold supplier locks or run in TLS callbacks. Its source and all attach/detach and lock-order paths require independent review; it is not a production-ready strategy or a claim that arbitrary nonparticipating modules can be detected. Canonical host/translator link maps, both guest ABIs, runtime identity, immutable supplier role and package/full checks remain required.
