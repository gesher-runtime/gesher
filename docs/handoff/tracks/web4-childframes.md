## Established boundary and primary contracts

PageScripts.messageListener explicitly excludes child frames; SupportLib.deliver hardcodes isMainFrame=true and caches replies by origin, so same-origin siblings cannot be distinguished. webMessage accepts guest-provided listener names without native-source rule revalidation: failure to inject is not a defense against a page forging the bridge envelope. Native currently subscribes the top-level WebMessageReceived only. Do not trust a page-supplied origin or frame/document identifier as authority.

AndroidX WebViewCompat source https://raw.githubusercontent.com/androidx/androidx/androidx-main/webkit/webkit/src/main/java/androidx/webkit/WebViewCompat.java and API https://developer.android.com/reference/androidx/webkit/WebViewCompat specify per-allowed-origin frames, listener-before-document-start script ordering, main-frame flag, source origin, frame-specific reply proxy and script removal for future documents. WebView2 documents top-level+child document-created injection (asynchronous completion), frame-specific message receive/post and frame destruction: https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2frame2 and nested child FrameCreated via https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2frame7 . Pinned SDK is 1.0.4258.31; actual runner runtime interface availability must be checked, not assumed.

## Bounded design and verification

- Subscribe to actual WebView2 frame-created/destroyed and navigation lifecycle with native-owned frame tokens and document generations; recursively follow supported nested frames, marshal callbacks on existing host/UI/JNI lifecycle. Fail closed if required interface or valid current frame/document origin is unavailable; do not fake nested support. Retire subscriptions, references and pending replies on frame/document destruction, replacement and host teardown.
- Derive source and frame identity from native WebView2 events, independently apply AndroidX origin rules at the receiving Java boundary before invoking the listener, and key reply proxies by native frame/document generation rather than origin. Route replies through that actual frame object and reject stale/destroyed generations. Preserve main-frame behavior, ordering, ABI and Web3 ownership gates.
- Preserve document script registration, ordered listener then scripts and removal. Audit actual asynchronous registration completion vs navigation before claiming document-start order; add a real completion barrier or another source-backed safe solution without weakening existing deadlines. Verify script runs before first page script in main, same-origin and cross-origin child frames.
- Explicitly investigate AndroidX/Chromium origin semantics for about:blank, srcdoc, opaque/sandboxed and inherited origins. Never treat absent/opaque identity as an allowed trusted origin by default or claim their contract closed without actual origin/effect evidence. Domain wildcard, default/explicit ports, scheme, redirects and malformed/forged message cases need positive and negative cases.
- CI-only local HTTP fixtures: two real distinct origins and at least two same-origin sibling frames plus nested and redirected/removed/navigated frames. Assert exact callback sourceOrigin/isMainFrame, listener-before-script ordering, per-frame reply isolation, stale proxy suppression and forged/disallowed-origin no-delivery. Run both Windows and actual single/device contexts, including actual native frame identity observations and original 14 Web3 gates. No physical keyboard/GPU/camera or unrelated geolocation/ports/other Web4 closure is implied. Build/compile all C/C++/Java/fixtures in CI only.

## Security review correction and research

WebView2's message source is a document URI, and deriving an origin from that URI does not detect a sandboxed HTTPS document with an opaque security origin. The current WIP can authorize such a document and is not safe to qualify. Also, minting the replacement token at navigation start can attribute a queued old-document message to the future document. A pending navigation can legitimately leave the old document alive; the test must distinguish that document's proxy from its replacement, not assume that every precommit callback is forbidden.

Chromium explicitly warns against inferring security origin from a sandboxed document URL: https://chromium.googlesource.com/chromium/src/+/main/docs/security/origin-vs-url.md . The CDP Runtime protocol describes an engine-provided context origin, unique context identifier, binding-call context ID and unique-context evaluation: https://chromedevtools.github.io/devtools-protocol/v8/Runtime/ . WebView2 documents flattened DevTools sessions for cross-origin frame targets: https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2_11 . This is a research direction, not a solution: actual opaque-origin values, binding readiness before page script, session coverage, default-world identity, destruction ordering, frame/main classification and race-free reply targeting must be established on the pinned runtime. Do not infer a mapping from URI or page-supplied data.
