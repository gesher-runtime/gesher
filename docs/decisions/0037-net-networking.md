# 0037 — Networking: Conscrypt over BoringSSL, Windows' trust store, connectivity from Windows

**Status:** accepted, 2026-10-24

## Context
Android apps use the network through libcore (sockets, DNS), Conscrypt (TLS and
most of JCA, over BoringSSL), OkHttp (`HttpURLConnection`), and the
Connectivity module (`ConnectivityManager`, served by ConnectivityService).
Gesher had libcore's sockets over Winsock ([0009](0009-socket-fds.md)) but no
BoringSSL, no Conscrypt or OkHttp on the boot class path, and a
ConnectivityManager that said there was no network.

## Decision
- **BoringSSL is a Windows library** (`cmake/aosp/boringssl.cmake`), built from
  the project's generated `android-sources.cmake`, like ICU4C
  ([0011](0011-libcore-natives.md)): Win32 threads, `ProcessPrng`. No
  assembly for now (`OPENSSL_NO_ASM`: the Windows x86-64 assembly is NASM's).
  `OPENSSL_NO_SOCK`: its socket BIOs call Winsock's `send`/`recv`, whose
  import-library members define names gesher-base defines; Conscrypt's one
  `SSL_set_fd` goes to `compat/net/fd_bio.cc`, a BIO over gesher-base's fds.
- **Conscrypt's natives are compiled on gesher-base's side**: a patch takes the
  POSIX branches of its `_WIN32` conditionals (its Windows port is for
  OpenJDK with MSVC), the Android branches for `FileDescriptor.descriptor` and
  `AttachCurrentThread`, and registers natives through System V thunks
  ([0006](0006-managed-abi.md)). `libjavacrypto.so` is a built-in library.
- **Conscrypt, OkHttp and BouncyCastle are dexed into core-libart.jar**
  instead of boot jars of their own. The boot class path is spelled out by
  every launcher, test and the boot image; adding jars would touch all of
  them for no behaviour of note (they are all boot class path classes on
  Android too), and in core-libart they are in the primary boot image. They
  stay out of the coremod, so the framework still compiles against
  Conscrypt's platform API stubs, as on Android. framework.jar carries its own
  copies of Conscrypt's aconfig flag classes; core-libart's come first and
  are generated by the same tool from the same release values.
- **The system CA store is written from Windows'**: when libjavacrypto loads,
  `$ANDROID_ROOT/etc/security/cacerts` gets Android's CA set joined with the
  roots Windows trusts for TLS servers (ROOT, AuthRoot, self-signed CA-store
  certificates; enhanced key usage honoured; Disallowed removed), as the
  `<hash>.<n>` PEM files Conscrypt and the network security config read.
  Writing the directory keeps both readers unpatched; doing it at load time
  follows changes to Windows' stores without a service. Android's set is kept
  because Windows fills its ROOT store lazily (roots are fetched on demand),
  so a root Windows has not needed yet may be missing from it.
- **ConnectivityService is Gesher's**, in the system server
  (`com.gesher.server.ConnectivityService`), with a small binder interface of
  its own (`com.gesher.net.IConnectivity`: snapshots and listeners), and
  `android.net`'s public classes are written in gesher-app.jar with the
  module's API. Building the Connectivity module (framework-connectivity, its
  AIDL, netd client and service-side) was rejected for now: most of it is
  about netd, eBPF and network agents, which Windows replaces, and apps only
  see the public API. A snapshot is text, so it crosses binder whole and
  compares with `equals`.
- **INTERNET is enforced in the process**, as Android does with the inet
  group: gesher-base refuses inet sockets and name lookups when
  `GESHER_INET=0` (set by the system server for packages without it) or after
  `gesher_set_inet_allowed(0)` (gesher-app's own process).
  ACCESS_NETWORK_STATE is enforced by the service.

## Consequences
- TLS, certificates and HTTP behave as on a phone, including the network
  security config (cleartext refused for new target SDKs) and roots a company
  or a filter installed in Windows.
- core-libart.jar and the primary boot image are larger.
- The Connectivity module's hidden API (netd, agents, keepalives, QoS) is
  absent; see docs/network.md's known gaps.
