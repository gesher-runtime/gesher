# Geocoder probe cancellation protocol

The adapter is a runspace-local set of scriptblocks: `Wait(int)` returns a Boolean, `Cancel()` requests cancellation on the same owned operation, `Status()` returns Started, Completed, Canceled or Error, `Result()` reads a successful result, and `Close()` performs only cleanup known safe for that adapter. An optional `Error()` supplies fault details. The decision helper invokes these on its calling runspace; no PowerShell scriptblock runs on a worker thread. Wait's first Boolean is the deadline decision. A false decision always fails even if completion races cancellation. Result is read only after a true first wait and Completed status. Terminal status and a signaled completion wait are required before cleanup. A blocked adapter call is contained by the independent process deadline, not by this protocol.

The CI fixture's wait is a controlled decision, not a timing benchmark. Its worker has actual started, cancellation, exit and disposal signals; it joins the thread before disposing resources. The late-completion case releases completion after the false decision and before Cancel. The noncooperative child announces entry to a blocking Cancel and is killed and reaped by its parent. This only demonstrates containment of the fixture process.

Microsoft documents [Cancel as a request](https://learn.microsoft.com/en-us/windows/win32/api/asyncinfo/nf-asyncinfo-iasyncinfo-cancel), [terminal statuses](https://learn.microsoft.com/en-us/uwp/api/windows.foundation.iasyncinfo.status), and that [Close must follow completion and prohibits further use](https://learn.microsoft.com/en-us/uwp/api/windows.foundation.iasyncinfo.close). The [AsTask documentation](https://learn.microsoft.com/en-us/dotnet/api/system.windowsruntimesystemextensions.astask) does not establish that its bridge callback has returned when the Task signals. Consequently the real adapter deliberately does not call Close: the probe process retains the projection until it terminates. A terminal operation and a signaled Task do not prove that an out-of-process Maps provider stopped. Projected Cancel/Status behavior and the fixture itself require Windows CI; configured positive geocoding and provider-level cancellation remain open.
